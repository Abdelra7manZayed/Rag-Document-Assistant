# 📚 RAG Document Assistant

A full-stack Retrieval-Augmented Generation (RAG) web app. Ask questions about your documents and get grounded, cited answers — no hallucinations from the LLM's own training data.

## Architecture

```
User Question
     │
     ▼
[Streamlit Frontend]
     │  HTTP POST /api/v1/query
     ▼
[FastAPI Backend]
     ├── Embed question (sentence-transformers)
     ├── Retrieve top-K chunks from ChromaDB
     ├── Build prompt (context + question)
     └── Call Ollama LLM → grounded answer
     │
     ▼
[Streamlit Frontend] ← answer + cited sources
```

## Tech Stack

| Layer | Tool |
|---|---|
| Embeddings | `sentence-transformers` (all-MiniLM-L6-v2) |
| Vector DB | `ChromaDB` (persistent, local) |
| LLM | `Ollama` (llama3.2, runs locally) |
| Backend | `FastAPI` + `uvicorn` |
| Frontend | `Streamlit` |

## Domain & Data

Domain: **Python Programming & Software Engineering FAQs**

Four source documents covering:
- Python fundamentals (types, memory, decorators, type hints)
- Advanced Python (generators, GIL, async/await, dataclasses)
- Software engineering (REST, SOLID, Docker, CI/CD, TDD)
- FastAPI guide (Pydantic, DI, CORS, lifespan, testing)

To swap in your own documents: put `.txt` or `.pdf` files in `docs/sample_docs/` and re-run the notebook.

## Setup & Run

### Prerequisites

| Tool | Version | Check |
|---|---|---|
| Python | 3.10+ | `python --version` |
| Ollama | latest | `ollama --version` |
| Git | any | `git --version` |

### Step 1 — Clone & create virtual environments

```bash
git clone https://github.com/<your-username>/rag-assistant.git
cd rag-assistant
```

**Backend:**
```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env        # edit if needed
```

**Frontend (separate terminal):**
```bash
cd frontend
python -m venv .venv
source .venv/bin/activate   # or .venv\Scripts\activate on Windows
pip install -r requirements.txt
cp .env.example .env
```

### Step 2 — Pull the LLM

```bash
ollama pull llama3.2
ollama serve               # keep running in background
```

### Step 3 — Build the vector store (run the notebook)

```bash
cd notebooks
jupyter notebook rag_pipeline.ipynb
# Run all cells top-to-bottom (Kernel → Restart & Run All)
# This writes the vector store to backend/data/vector_store/
```

### Step 4 — Start the backend

```bash
cd backend
uvicorn app.main:app --reload
# Open http://localhost:8000/docs to test via Swagger UI
```

### Step 5 — Start the frontend

```bash
cd frontend
streamlit run app.py
# Opens http://localhost:8501 in your browser
```

### Run tests

```bash
cd backend
pytest tests/ -v
```

## Environment Variables

### Backend (`backend/.env`)

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama server URL |
| `OLLAMA_MODEL` | `llama3.2` | Model name to use |
| `VECTOR_STORE_PATH` | `data/vector_store` | Path to ChromaDB data |
| `COLLECTION_NAME` | `rag_docs` | ChromaDB collection name |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Sentence-transformers model |
| `TOP_K` | `4` | Chunks retrieved per query |
| `CORS_ORIGINS` | `["*"]` | Allowed frontend origins |

### Frontend (`frontend/.env`)

| Variable | Default | Description |
|---|---|---|
| `API_BASE_URL` | `http://localhost:8000` | Backend base URL |

## API Reference

### GET /health
Returns `{"status": "ok"}` — use to verify the server is up.

### POST /api/v1/query

```bash
curl -X POST http://localhost:8000/api/v1/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What is a Python generator?"}'
```

Response:
```json
{
  "answer": "A generator is a function that uses yield...",
  "sources": [
    {
      "source": "python_advanced.txt",
      "chunk_id": "python_advanced.txt_2",
      "excerpt": "A generator is a function that returns an iterator..."
    }
  ],
  "model_used": "llama3.2"
}
```
